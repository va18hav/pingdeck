# Database Schema

PingDeck uses PostgreSQL 17 as both its system of record and transactional job queue.

## DDL

```sql
CREATE TABLE endpoints (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    target_url TEXT NOT NULL,
    -- Front door: which provider's signature scheme to verify at ingest.
    -- '' means no inbound verification (accept anything).
    provider TEXT NOT NULL DEFAULT '',
    -- Front-door secret, provided by the source (e.g. Stripe/GitHub webhook secret).
    -- Must be set when provider != ''.
    inbound_secret TEXT,
    -- Back-door secret, generated by PingDeck (whsec_...). Signs every outbound
    -- delivery with X-PingDeck-Signature so the user's server can verify us.
    signing_secret TEXT NOT NULL UNIQUE,
    max_retries INT NOT NULL DEFAULT 5,
    timeout_ms INT NOT NULL DEFAULT 10000,
    slack_webhook_url TEXT,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TYPE event_status AS ENUM (
    'PENDING',
    'PROCESSING',
    'DELIVERED',
    'RETRYING',
    'FAILED'
);

CREATE TABLE webhook_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    endpoint_id UUID NOT NULL REFERENCES endpoints(id) ON DELETE CASCADE,
    headers JSONB NOT NULL,
    raw_body BYTEA NOT NULL,
    content_type TEXT,
    status event_status NOT NULL DEFAULT 'PENDING',
    attempt_count INT NOT NULL DEFAULT 0,
    next_retry_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    locked_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Partial index for the worker claim query (FOR UPDATE SKIP LOCKED)
CREATE INDEX idx_webhook_events_queue
ON webhook_events (next_retry_at ASC)
WHERE status IN ('PENDING', 'RETRYING');

-- Index for dashboard queries filtered by endpoint and time
CREATE INDEX idx_webhook_events_endpoint_created
ON webhook_events (endpoint_id, created_at DESC);

CREATE TABLE delivery_attempts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    event_id UUID NOT NULL REFERENCES webhook_events(id) ON DELETE CASCADE,
    attempt_number INT NOT NULL,
    response_status INT,
    response_headers JSONB,
    response_body TEXT,
    execution_time_ms INT NOT NULL,
    error_message TEXT,
    attempted_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_delivery_attempts_event_id
ON delivery_attempts (event_id, attempt_number DESC);
```

## Secrets Model

Two independent secrets protect the two hops of a proxied webhook (the trust chain, modeled on Convoy/Svix):

```text
[Provider] --signs w/ inbound_secret--> [PingDeck verifies at ingest] --signs w/ signing_secret--> [User's Server]
```

- **`inbound_secret`** — provided by the source. PingDeck uses it in the ingest handler to verify
  the request *before storing it* (invalid → `401`, nothing reaches the queue). Stored per-endpoint,
  and echoed back in GET/list responses (it's the user's own pasted value — showing it leaks nothing).
- **`signing_secret`** — generated by PingDeck (`whsec_` + 32 random bytes hex, via `crypto/rand`)
  when the endpoint is created, and returned **once** in the create response. The worker computes a
  fresh HMAC at dispatch time, so retries and manual replays always carry a valid, current signature.
  Regenerated via `POST /endpoints/{id}/rotate-secret` (new raw secret revealed once; the old one
  dies immediately). GET/list/update responses only ever carry a server-side mask
  (`whsec_<first4>…<last4>`), so the raw value never re-surfaces after its one reveal.

The `whsec_` prefix is pure convention (borrowed from Stripe/Svix): it makes the value recognizable
as a secret to secret-scanning tools, log redaction regexes, and humans. The HMAC algorithm itself
does not care about the prefix.

## Endpoint Lifecycle (API)

- **`PUT /api/v1/endpoints/{id}`** — full update (all editable fields sent every time; `signing_secret`
  is never settable through it — only rotate changes it).
- **`DELETE /api/v1/endpoints/{id}`** — hard delete; the `ON DELETE CASCADE` FKs take its events and
  attempts with it in the same statement.
- **`POST /api/v1/endpoints/{id}/rotate-secret`** — swap the signing secret; raw new value returned once.

## Core Queue Query (Worker Claim)

Workers claim batches of due events atomically without blocking concurrent workers:

```sql
WITH due_events AS (
    SELECT id
    FROM webhook_events
    WHERE status IN ('PENDING', 'RETRYING')
      AND next_retry_at <= NOW()
    ORDER BY next_retry_at ASC
    LIMIT $1
    FOR UPDATE SKIP LOCKED
)
UPDATE webhook_events e
SET status = 'PROCESSING',
    locked_at = NOW(),
    updated_at = NOW()
FROM due_events
WHERE e.id = due_events.id
RETURNING e.id, e.endpoint_id, e.headers, e.raw_body, e.content_type, e.attempt_count;
```
